# CLAUDE.md

Локальный Python 3.11 оркестратор: отправляет задачу Antigravity через Agent-Bridge, ожидает без LLM, проверяет результат Codex и повторяет исправления при `RETRY_NEEDED`. Новые сообщения пользователю и логи пишите по-русски. Runtime-зависимостей вне стандартной библиотеки нет.

## Работа с проектом

```powershell
python -m pytest -q -rs
python -m pytest tests/test_orchestrator.py -v -rs
```

`pyproject.toml` добавляет `src` в `pythonpath`. В тестах используйте `MockBridgeClient`, `MockCodexVerifier`, временные каталоги и поддельные исполняемые файлы. Никогда не запускайте реальные `agy`, `agent-bridge` или `codex` в тестах. Автоматическая фикстура блокирует вызов `agy models`; не обходите её. В обычной Windows-оболочке тесты должны проходить без `PYTHONIOENCODING` и `PYTHONUTF8`. Не оставляйте отчёты и `orchestrator_logs` в корне репозитория. Не делайте `git commit`/`git push` в рамках тестов.

## Жизненный цикл

- `Orchestrator` принимает зависимости через конструктор. `ModelRouter` создаётся лениво при `create_task()` или CLI `models`; команды чтения, отмены и восстановления сами по себе не вызывают `agy models`.
- `BridgeClient` запускает отдельный процесс Agent-Bridge и использует MCP JSON-RPC через stdio. `request_id` устраняет дубли только внутри владеющего процесса Bridge и не гарантирует повторяемость после перезапуска. `wait_task` и `cancel_task` работают лишь с задачами этого процесса.
- `NonLLMWaiter` ожидает в коротких интервалах. Общий бюджет `total_task_timeout_sec` отсчитывается от сохранённого `started_at` для всей задачи, включая все повторы и восстановление. Число повторов само по себе не ограничено.
- Классификация статусов Bridge сосредоточена в `statuses.py`; не заводите копии наборов статусов в других файлах. При восстановлении `completed` из сохранённого состояния можно проверить через `get_result`, а `running`/`queued` с `from_state` означают осиротевшую задачу: ожидание и отмена невозможны, требуется ручная проверка агента перед повторным запуском. Для живых `running`/`queued` ожидание возобновляется. Живой ответ об осиротевшей задаче приводит к отказу без повторной отправки.
- `CodexVerifier` передаёт UTF-8 промпт через stdin в `codex exec --json -o <file>`; окончательный вердикт берётся из выходного файла, а JSONL событий используется как свидетельство запуска и результата тестов. Неподтверждённые обязательные тесты не считаются пройденными. `_workspace_fingerprint` учитывает Git diff и содержимое неотслеживаемых файлов, исключая кэши.
- `RetryController` формирует уточняющий промпт и итоговый отчёт. Каждое терминальное завершение через `run_task`, `recover` или `cancel_task` записывает `orchestrator_report_<id8>.md` в `task.cwd`; ошибка записи не должна менять статус задачи.

## Хранение, отмена и наблюдение

`repository.py` хранит задачи и события в SQLite WAL, ограничивает число активных задач и защищает уже отменённую строку от перезаписи устаревшим объектом: сохраняются статус, причина отмены и `finished_at`. Для изменения схемы одновременно обновляйте сериализацию `Task` и SQL.

`progress.py` пишет ленту в `[progress].log_dir` или рядом с БД в `orchestrator_logs`; интервал задан `poll_interval_sec`. CLI `watch [ID] [--once]` читает БД и лог, показывает время событий в местном часовом поясе и не создаёт отсутствующую БД. CLI `cancel` помечает задачу в БД без обращения к новому экземпляру Bridge. Живой оркестратор замечает отмену при следующей проверке; если он не работает, агент требует ручной проверки. Внутренний `cancel_task()` по умолчанию по-прежнему уведомляет свой Bridge.

`config.py` загружает путь из `--config`, `ORCHESTRATOR_CONFIG` или `config.toml`, затем использует `config.example.toml` или значения по умолчанию. Не изменяйте личный `config.toml` для тестов. CLI: `run`, `submit`, `status`, `list`, `recover`, `cancel`, `models`, `report`, `watch`.
